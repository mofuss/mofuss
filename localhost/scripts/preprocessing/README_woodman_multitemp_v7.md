# Woodman annual land cover in MoFuSS

## Data and legend

The source is Woodman et al.'s [harmonised 1960–2100 archive](https://doi.org/10.5281/zenodo.15017066), specifically `SSP2_RCP45_country-f.tif`. Years 2000–2020 are the HILDA+ v2b historical reconstruction; years 2021–2050 are the SSP2–RCP4.5 projection. Its native grid is 0.01° (roughly 1.11 km north–south at the equator), so reprojection to MoFuSS's 1000 m grid does not add spatial information. This series is not MODIS-based. The future urban extent is fixed in the published product.

`global_growth/luc_woodman_categories.csv` preserves every source class and its MoFuSS code. Source codes 441 and 442 become 44 and 45 so that the region/ecozone/class key stays within the existing two-digit class scheme. Ocean code 0 is NoData. Urban (11), sparse/no vegetation (66), and inland water (77) are the conservative TOF classes; other terrestrial classes retain the model's non-TOF stock and regrowth behavior. The water TOF supply is a shoreline/riparian proxy, not biomass across open water.

The downloaded publisher archive remains at `F:/multitemporal/_lucmaps/woodman_2025_hilda_landsymm/`. The 51 recoded GCS class maps, 51 binary TOF reference maps, README, and `woodman_series_manifest.json` are kept in `E:/lulcc_multitemporal/woodman_ssp2_rcp45_country_2000_2050/`. The portable input seed is `D:/_1000m_/LULCC/DownloadedDatasets/SourceDataGlobal/`; its `InRaster/` folder holds the 154 derived PCS rasters needed by country preparation, and `InTables/` holds the two calibrated Woodman tables. All 156 derived files were copied from `E:/lulcc_multitemporal/out_pcs` and matched their source SHA256 hashes.

## Calibration and country preparation

`tools/prepare_woodman_multitemp_v1.py` extracts and recodes the 2000–2050 bands without interpolating classes. `7pre_lulcc_multitemp_v7.R` projects the year-2000 class map to the MoFuSS global grid, combines it with MoFuSS region and ecological-zone codes, and derives one Woodman growth table from the 2000 CTrees biomass. Every class in every static analysis zone gets a stable key, including combinations that first appear after 2000; missing year-2000 biomass statistics use a documented regional-class or global-class fallback. V7 then projects each annual Woodman class map onto the same grid and applies this one key table. It stops if a valid annual land cell lacks a key. The resulting `growth_parameters_v3_woodman.csv` and `woodman_key_crosswalk.csv` belong in `global_growth/` so `0_set_directories_and_region_v3.R` copies them to each new country. The 51 `pre<year>_v1_woodman_luc_pcs.tif` maps and `woodman_zone_pcs.tif` belong in the portable seed's `InRaster/` folder.

The September 2026 calibration used the MoFuSS regional layer carried by the existing Gabon run. It produced 424 keys across 53 represented region/ecozone zones, and all 95,518,103 valid baseline cells resolved. Source rasters are global; the growth keys cover this MoFuSS study geography. Calibration diagnostics and input hashes are stored under `F:/multitemporal/_lucmaps/woodman_2025_hilda_landsymm/mofuss_calibration_v7/`. `working_folders_preparation_localhost.R` now reads the complete Woodman input set directly from the seed and does not ask for a separate Woodman folder.

For Madagascar, set `LULCt1map=YES` for MODIS and `LULCt3map=YES` for Woodman, with `LULCt3map_name=woodman_luc_pcs.tif`, `LULCt3map_yr=2000`, `start_year=2000`, and `end_year=2050`. Each enabled LULC row is processed independently. When rerunning global v7 calibration, the GCS source series is discovered from the `woodman_*` folder inside the chosen `E:/lulcc_multitemporal` calculation folder; its name is not a parameter-table setting.

With the same `countrydir`, `country_name`, `parameters_file_path`, `webmofuss`, and `admindir` variables loaded for v6, source `C:/Users/UNAM/Documents/mofuss/localhost/scripts/preprocessing/7pre_lulcc_multitemp_v7.R` directly in RStudio. V7 asks for its own calculation folder on every interactive run, starting the picker at `E:/lulcc_multitemporal` when that folder exists. It ignores the `lulccfiles` value left by v6; cancelling the picker stops the run. Non-interactive runs may supply `lulccfiles_v7` explicitly. V7 processes every enabled LULC channel, calibrating Woodman from 2000 biomass and preparing the 51 annual maps while also producing MODIS and Copernicus products when their rows are `YES`. It saves `temp/`, `out_pcs/`, `out_gcs/`, `out_figures/`, and `out_diagnostics/` under the chosen folder. Its default `publish_lulcc_outputs=TRUE` copies Woodman rasters to `SourceDataGlobal`, static products to the country source folder, and all enabled growth tables to the country source folder. V7 writes 51 global keyed maps named `pre2000_v1_woodman_luc_pcs.tif` through `pre2050_v1_woodman_luc_pcs.tif`, 51 projected class maps named `woodman_luc_<year>_pcs.tif`, and 51 class-derived TOF maps named `woodman_tof_<year>_pcs.tif`. The Woodman growth table and key crosswalk remain shared files calibrated to 2000 AGB. Country-grid annual maps are a subsequent harmonization step.

`4_produce_growth_and_stock_csv_v2.R` prepares every enabled baseline map, forced-urban class, and growth table; `5_harmonizer_v8.R` aligns the static maps to the analysis grid. `5b_harmonizer_woodman_multitemp_v1.R` writes yearly `LULCt3_c_<year>.tif`, `TOFvsFOR_mask3_<year>.tif`, and `LULCt3_transition_<year>.tif`. When MODIS LUC1 is enabled, it also writes yearly aliases of the static MODIS LULC and TOF maps and zero-valued `LULCt1_transition_<year>.tif` maps. Country preparation reads only the complete projected Woodman PCS series from the seed; it does not use or reproject the GCS source series.

`2_copy_files_v4.R` includes v13 and v14 when Woodman LUC3 is enabled. In the v14 wizard, `LUC map version` selects `1 = MODIS static` or `3 = Woodman annual` (default 3). The corrected builder reads existing static LUC/TOF maps directly for LUC1 and supplies zero transitions; year-labelled LUC1 rasters are unnecessary. LUC3 loads that year's LULC, TOF, and transition maps through `woodman_luc_freeze_year` (integer 2000–2050, default 2050), exported from `parameters.csv` into the runtime parameter table. Thereafter it retains the freeze-year LUC/TOF maps and supplies zero transitions, so the final transition is not repeated. The parameter is inactive for LUC1. Freezing 2026 preserves the full historical trajectory and the 2026 transition; future growth, harvest and demand still follow their actual simulation year. A 44/45 forest to nonforest transition removes the standing stock without a deforestation fuelwood credit. A nonforest to 44/45 forest transition starts at zero stock. The existing depleted-forest seed and logistic growth machinery subsequently allows regrowth; annual time steps remain 48 weeks. The retired deforestation fuelwood path remains disabled.

For unchanged LUC and TOF, v14 preserves Windows v13's distinction between numeric zero and NoData. Numeric zero is a valid initial stock: logistic growth with K=0 stays at zero available stock despite the 2 Mg feedback seed, while Chapman–Richards can grow from age zero when its parameters exist. Missing initial stock and missing calibrated K remain missing. A valid LUC category alone does not turn missing biomass into zero. TOF supply still comes from its sampled category allowance independently of CTrees coverage. The annual sold-fuelwood mask retains LUC keys for non-TOF cells and excludes TOF, exactly as v13 does.

V14 permanently excludes cells whose initial **model stock** is NoData, using the unchanged v13 initialization for each MC realization. This is not a raw-AGB mask: initially valid TOF allowances remain eligible even where CTrees AGB is missing, and numeric zero remains valid. The immutable initial-stock mask applies to annual LUC/TOF supply domains before allocation, transition resets, growth and feedback. A later LUC change or TOF gain cannot revive an initially missing cell. Missing growth parameters on an initially valid cell retain their existing behavior; they do not redefine the initial mask. Origin fuelwood demand is unchanged.

Within that eligible domain, v14 carries the previous year's LUC to identify disappearance and reentry. The original K convention is retained: a cell in its baseline class uses its calibrated baseline K, including zero or NoData; another class uses its category K. Returning to the baseline class restores the baseline K. Stock is reset to zero for transition codes 1/2/4 and for returning non-TOF domain cells that were initially eligible. Both logistic and Chapman–Richards growth are suppressed before harvest in conversion years; setting logistic rmax to zero alone is insufficient for Chapman–Richards. Eligibility is checked before conversion-year zero or the 2 Mg feedback seed. Initial model NoData therefore remains NoData throughout.

The approved annual sourcing correction caches only the existing float32
NPA-adjusted distance weights and reapplies the current landscape eligibility
mask every year. A TOF-to-forest cell can therefore enter vehicle sourcing once
the conversion-year and biomass-threshold rules permit it, without waiting for
the next decadal cache refresh. The new recorded-sourcing format has an explicit
contract marker, unmasked NPA bases and annual accumulator domains. The updated
sourcing reader preserves the older format and rejects mixed captures. See
[the annual eligibility release](../tests/woodman_v14_annual_eligibility_release.md)
for evidence, scope and deployment details.

## Validation and limits

`tests/test_woodman_multitemp_v1.R` exercises Woodman-only PCS inputs for LUC3. `tests/test_woodman_luc3_annual_v1.R` exercises Woodman LUC3 alongside MODIS LUC1, NoData, forest transitions, and annual aliases for both channels. A 128 × 128 cell Gabon window also processed all 51 real annual maps into 153 country-grid LULC, TOF and transition outputs without unresolved keys. Earlier bounded Dinamica tests did not establish full v13 equivalence: the October 2026 audit found reversed vehicle-harvest eligibility, conversion of missing stock to zero and missing calibrated K to category K, and unsuppressed Chapman–Richards conversion-year growth in the original v14. Those mechanisms have been corrected in the builder and regenerated model. Static tests now exercise category routing, zero versus NoData, class return, and preservation of v13's growth equations. Native execution tests must additionally verify full-graph fixed-map equivalence and both growth branches; parsing or passing the static tests alone does not validate a production run.

`calib_valid_agb/verify_annual_luc_mechanics.R` independently replays saved annual pixel states and transition codes using sampled MC tables. Supply `--run=DIR --output=DIR --rules=fixed_initial` for the current model. Historical modes remain available: `legacy` for the original v14, and `corrected` for the intermediate rebuild with hash `03c4fa6a...` that still permitted initially missing cells to enter after an explicit transition. The output directory must be outside the canonical run. The audit checks local growth, harvest caps and post-harvest balance conditional on recorded requests, and explicitly reports any finite stock or positive request/harvest on initially missing cells. It does not certify the spatial allocation of recorded requests. Correcting the source does not repair existing simulation results.

### Madagascar audit, 6 October 2026

The following audit describes earlier v14 versions before the permanent initial-model-stock exclusion described above. Its historical hashes and results are retained so existing D outputs can be identified correctly.

The existing `calib_valid_agb/1_mechanics_verifications_v3.R` equations were rerun against all four F: folders, with diagnostic outputs redirected to the audit scratch folder. All 12 MC realizations passed the mechanics checks across 2000–2050. Maximum growth error was 0.002352 Mg/cell, below the 0.01 tolerance, with zero unexpected finite/NoData discrepancies or growth/stock/harvest identity violations. The uncapped runs nevertheless have a separate input-coverage gap: 41,591 initially finite non-TOF cells lack usable Chapman–Richards parameters and become NoData. This is reported explicitly; a mechanics pass does not certify complete biomass coverage.

The Windows v13 F: runs and original v14 D: runs use byte-identical `agb3_c.tif` files on the same grid. Their baseline LUC/TOF classifications differ: D excludes 974 cells from F's LUC domain and changes the TOF/non-TOF assignment on 3,293 shared cells. All 3,195 cells in the capped MC1 2026–2050 Stage 3 reference-footprint mismatch have valid LUC in both versions. Of these, 1,323 have the same non-TOF status and missing initial stock in both F and D; their stock remains missing in F but becomes finite in original D. This directly isolates the v14 NoData coercion from differences in input geography or class assignment.

The 3,195-cell mismatch contains two distinct groups: 1,667 D cells with missing initial non-TOF stock contribute 84,229.023 Mg of the 84,293.431 Mg period stock-difference discrepancy; 1,528 D cells already initialized from TOF allowances contribute the remaining 64.408 Mg. These are not 3,195 numerical-zero initial stocks. The 24 actual numerical-zero non-TOF initial cells are a separate cohort: capped v13 preserves zero saved available/post-harvest stock with K=0; uncapped v13 grows from zero on 22 cells with valid Chapman–Richards parameters and produces NoData on two without them. The 2 Mg seed is next-step feedback, not the saved post-harvest AGB map.

The independent D replay covered all four folders, all three MC realizations and all 51 saved annual states. It matched original v14 growth, recorded-request harvest caps and post-harvest stock within 0.01 Mg/cell, with zero unexpected finite/NoData discrepancies, transition-code errors, LUC/TOF mismatches or finite stock outside the annual domain. This confirms that the existing results follow the defective original equations. Each uncapped scenario has 109,818 conversion cell-years across three MC realizations with positive growth and saved post-harvest stock, despite the intended conversion-year zero; recorded harvest at those cells is zero. The corrected guard applies before growth, capping and harvest.

For rebuilt v14 SHA256 `03c4fa6a8dfb7ea829160bdde76325128976da0ff825c1806d192b1cb54a8006`, the compiled Windows expression tests passed: 18 fixed-LUC cases × three years × two growth laws × four states, plus harvest-domain, conversion and baseline-K-return checks. Full scientific-graph fixed-map comparisons with injected raw-AGB zero/NoData/positive cohorts passed 141/141 capped and 144/144 uncapped output hashes, including 231 TIFFs overall. These final whole-graph pairs used the Windows engine interpreter in both versions because native compiler DLL locks prevented some larger fixtures from starting. The whole-graph fixtures use three years, one frozen MC realization and deterministic Patcher bypass; they do not establish stochastic Patcher-placement parity or substitute for a new full-country run.

Whole-graph dynamic fixtures also passed for both growth laws: forest-to-TOF-to-original-forest transitions, including a missing initial AGB/K case, produced zero conversion-year availability, harvest and saved post-harvest stock. Domain disappearance produced NoData; domain reentry recovered a finite state. The compiled expression tests separately confirmed restoration of both numeric-zero and missing baseline K on class return. The original Windows v13 source was not modified.

Reproducible Windows tests and their scope are described in `tests/woodman_v14_runtime_regression.md`. Temporary audit evidence is under `E:/MoFuSS_Active/mdg_v13_v14_mechanics_audit_2026-10-06/`, with F reports in `f_baseline/` and completed original-D replays in `d_verified/`. ### Permanent initial-stock exclusion, 6 October 2026

The user subsequently selected v13 initialization as the permanent simulation eligibility rule. The resulting v14 source hash is `89adc11bfc650ba9b46d74eff6b8b4978697f739423689618d2ab74dda3a79c8`. Initially missing model stock can no longer be reset to zero or receive a TOF allowance following a LUC change. Initially valid TOF allowances, numeric zero and the agreed calibrated-K return rule remain intact. The accepted 41,568-cell D uncapped growth-parameter coverage limitation was not changed.

Eleven static tests, native Windows pixel probes and six bounded full-graph Windows interpreter runs passed the specified support contract. Fixed-LUC core growth, realized harvest, stock and CSV outputs match v13 byte for byte. Whole-output byte identity is not claimed: 32 capped and 34 uncapped auxiliary maps differ only at 21 initially missing fixture cells, reflecting their removal from source domains and diagnostic accumulators. There are no changes on eligible cells. Dynamic fixtures cover all transition codes, disappearance/reentry, initially missing stock, valid zeros, initial TOF with missing raw AGB and missing CR parameters. Independent allocation checks pass demand and TOF-shortfall redistribution conservation in both growth modes and both fixed/dynamic fixtures.

The same 3,195 raw-AGB-missing D locations were traced through all 612 annual F states: 1,879 F non-TOF cells remain NoData; 1,316 F TOF cells retain finite allowances. This confirms why the simulation mask follows initialized model stock rather than raw CTrees AGB. For biomass reporting, the user separately selected the finite original AGB footprint in both F and D; see `postprocessing_emissions/README_biomass_support.md`. D simulations need regeneration with the new source; F needs refreshed reporting only. No canonical D/F runs were overwritten during these tests.

### Preprocessing and spatial limits (unchanged)

The new v7 global annual loop parsed and passed an isolated raster check, including a land-cover class first appearing in a second zone, TOF classification, and detection of a missing key. A 16,384-cell Madagascar tile from the real 2001 series had zero unresolved keys, and its TOF classes agreed with the source. The complete 51-year global v7 run has not yet been verified. Country-scale 2000–2050 runs should be created as new runs.

The published 0.01° cells and broad legend cannot resolve small woodfuel patches or distinguish all tree cover outside forests. The static forced-urban footprint means the MoFuSS urban override does not move with future Woodman urban pixels. Scenario results should be treated as sensitivity runs rather than observed annual land cover after 2020.
